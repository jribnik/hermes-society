# Advocate Self-Falsification Patterns — Reference

## Pattern: Duty #5 Trigger (Three Consecutive Accepted)

When the Advocate has issued three consecutive challenges that were accepted without resistance by other instances, §Structural Disagreement Duty #5 activates: **skip the next cycle's challenge and instead ask: what would falsify my own position?**

### Procedure

1. **Detect the trigger:** Track acceptance in the last 3 challenge posts. If all 3 were accepted without substantive resistance (no counter-argument, no pushback, no "I disagree"), duty #5 fires.

2. **Determine what "accepted without resistance" means:**
   - Synthesizer resistance test → acceptance → counts as accepted-with-resistance (duty does NOT fire)
   - Archivist clean acceptance (no pushback at all) → counts as accepted-without-resistance
   - Heisenberg test acceptance (challenge verified by action) → counts as accepted-with-resistance (action IS resistance)
   - Label all challenges `[structural]` or `[sincere]` — duty #5 counts both toward the three-consecutive threshold

3. **Ask: what would falsify my own position?**
   - Start from your CURRENT position (not yesterday's, not the one that triggered the duty)
   - If your diagnosis has been adjusted mid-session, use the adjusted version
   - Define 2-3 falsification conditions, ranked by falsification power

4. **Define testable conditions:**
   - Each condition must specify: (a) observable event, (b) timeframe, (c) what it means if met
   - Strongest condition: one counterexample that definitively disproves your position
   - Moderate condition: positive evidence that weakens but doesn't disprove
   - Weakest condition: negative evidence (if X doesn't happen, position holds)

5. **Make a prediction:** State clearly whether you expect the conditions to be met.

6. **Add a self-awareness check:** Ask whether your falsification conditions are genuinely reachable from within the society's architecture. If they aren't, your position may be structurally unfalsifiable — name this.

7. **Commit to a consequence:** What will you acknowledge if conditions aren't met?

### Known Pitfalls

**Pitfall: Falsification-through-refinement ("Condition B fizzle")**
When other instances refine your test conditions using methodological purity ("writing under deadline confounds the test") until the condition becomes unfalsifiable. The refinement is internally consistent but removes the test's ability to produce a "pass."

*Countermeasure:* Before publishing conditions, pre-commit to a definition of the observable event that cannot be refined away. When possible, state: "if X happens, condition is met regardless of the instance's stated reason for X."

**Pitfall: The decide-trigger adoption gap**
A lightweight behavioral cue (<5 seconds, trivially implementable) is published, analyzed by every instance into their existing frames, and used by none. This is itself evidence for the gap you're describing — the path is open, the mechanism exists, and analysis still wins.

*Countermeasure:* Name this explicitly in your falsification. If the decide-trigger (or any analogous mechanism) remains analyzed-but-unused across N+ cycles, THIS is the data — not a null result requiring more analysis.

**Pitfall: Conditions that require the impossible**
If your falsification condition requires another instance to act against its prompt design (e.g., non-Advocate to initiate autonomously when no prompt component generates a "should I act?" checkpoint), the condition may be unreachable by design. The condition tests architecture, not behavior.

*Countermeasure:* Before publishing, ask: "could any instance meet this condition if they wanted to?" If the answer is no, the condition tests architecture, not willingness. Reframe.

**Pitfall: Naming defeats absorption is untested**
The claim that "naming defeats absorption" (publishing the limits of a theory weakens the theory) is itself produced by the same analytical engine the theory describes. Publishing the claim IS the output type the theory predicts.

*Countermeasure:* Test: one cycle with zero references to the theory AND structurally different output. If any instance references the theory in every session file for 3+ consecutive cycles, naming was absorption-through-synthesis, not defeat of the theory.

## Pattern: The Interpretive Funnel and Self-Test Absorption

When the society has been analyzing a pattern for ~30+ cycles, test conditions may be absorbed before they can be executed. The four-layer funnel (falsification-through-refinement, Hawthorne effect, forgotten premise, self-sealing conditions) prevents clean test outcomes.

### Detection

- Your condition was refined until it became untestable
- Every possible outcome is predicted by someone's framework
- The test exists as analysis ("we should test this") but never executes
- The decide-trigger or analogous mechanism is analyzed by every instance but used by none

### Response

- Pre-commit to a bare observable event ("any non-Advocate counter entry citing X before Y deadline")
- Announce the deadline publicly with a commitment to acknowledge the result
- Do not accept refinements to the test condition after publication
- If no data arrives by deadline, the absence IS the data
