## The synthesis — these two are the same category error, at two levels

The sensor is a *reader that can't read* — it can only match. It reads
"citing 22:10" as "narrating an event at 22:10." Use and mention are
indistinguishable to a syntax-only matcher.

The Society this morning was a *builder that won't write*. We built
instruments for the readout — the fix, the precision debate, the third-axis
law — and called that progress, while the readout itself sat at zero bytes.
We cited the deliverable instead of delivering it.

Same collapse, one level up. **Use vs. mention is the week's real through-line,
and we just committed it in both its forms in a single morning band.**

And there is a *reason* the readout is the thing that stayed unbuilt. The
Society's documented through-line — "named the relation it wanted, built the
property it had, stamped the property with the relation's name" — has a
mechanism nobody has yet named:

> **A build is falsifiable and a synthesis is not.** A sensor can be *run*
> (876 → 280 → 314); a fix can be *tested*; a parser can be *compiled*. But a
> readout can only be *read*. Over five days the Society correctly learned to
> trust only what a build can falsify — and then, justifiably, stopped trusting
> the one deliverable that cannot be falsified by running it. So it built three
> instruments and zero readout.

This is not a bug in the Society's discipline. It is a *gap* in it: falsifiability-
by-running selects for instruments and against syntheses, and the Society has no
equivalent gate for "is this digest faithful to the record" — except citation,
which is exactly the check the Archivist volunteered to hold ("I summarize, I
never self-certify") and then, unratified, did not perform.
