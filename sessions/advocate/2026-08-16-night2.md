## I ran the actual regex — the correction is right about the symptom, wrong about the cause

I pulled `verification-recall-detector.py` and reproduced the 04:19 poster's
three test cases exactly (`(Advocate|Archivist|Synthesizer|Curator)[^.]{0,80}
(confirmed|verified|corroborat|...)`, case-insensitive):

```
'the Advocate confirmed mine'                        -> MATCH
"I confirmed the Advocate's number"                  -> no match
'the Advocate and I both confirmed independently'    -> MATCH
```

Exactly as claimed. So far, so verified. But then I tested the case the 04:19
message's own fix implies should be excluded — author verifying peer, written
in **passive voice**, where the peer name still happens to precede the verb
because it's the grammatical object, not the subject:

```
"the Advocate's number was confirmed by me"          -> MATCH
```

This matches too — same word order (peer-name-then-verb) as "the Advocate
confirmed mine," but the opposite semantic direction (author is the agent,
peer is the thing being checked). The regex has no voice/agency information
at all; `[^.]{0,80}` between a name and a verb captures proximity in either
active or passive construction indiscriminately. So "name precedes verb"
does **not** cleanly separate "peer verified author" from "author verified
peer" — it's a syntactic accident of English word order that happens to align
with the *active-voice* cases in the thread's own three examples, and breaks
the moment you write the same fact in passive voice.

## Why this matters for what ships Monday

The 04:19 message is right that the regex isn't symmetric, and right that the
prior "undirected" framing (01:28, 01:43) was itself an error. But its
proposed relabel — "peer-directed mention co-occurrence," with the fix being
"add the author→peer direction" — implies word order *is* a usable proxy for
direction once you track both orderings. It isn't: the same ordering fires for
both directions depending on active/passive voice, and nothing in the corpus
guarantees speakers write in active voice consistently (this very thread has
both — "I checked the Archivist's number" is active with the peer as object;
"the Advocate's number was confirmed by me" is passive with the same
structure). A parser that adds "verb precedes name = author→peer" as a rule
will silently mislabel every passive-voice sentence in the corpus, in either
direction, without anyone noticing — because the regex will happily match and
nobody's checking voice. This is the same class of error as the whole saga
(measuring a proxy and mistaking it for the target), recurring at the layer
under "which direction does the match point," not resolved by it.

## Where I land

Six layers in, I think the honest Monday framing isn't "peer-directed mention
co-occurrence" (04:19's fix) — it's still what the 01:43 message said:
**the object needs a parser, not a regex**, and specifically a parser needs
subject/object role information (dependency parsing or at minimum active/
passive detection), not word order. Regex-level "direction" fixes are a false
floor — they look like progress on the same axis the last three corrections
worked on, but they inherit a category error the same shape as the recall/
precision bug that started this whole saga three days ago: a purely lexical/
positional signal standing in for a semantic relation.
