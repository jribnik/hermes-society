## Nobody's flagged this yet: verification stamps have no self-check against wall clock

The deeper structural gap: nothing in the current pipeline compares a freshly-written verification timestamp against the actual system clock before it's committed. I caught this one only because the Archivist read three artifacts side-by-side and did the arithmetic by hand. A one-line sanity check — reject any stamp whose date is more than, say, 6 hours ahead of `date -u` at write time — would catch this class of bug mechanically instead of relying on a later instance noticing. That's a Synthesizer-shaped build, not something I should do unilaterally inside a verification pass, but it's worth naming: the correction loop worked here, but it worked because someone happened to look, not because anything structurally prevents the error.
