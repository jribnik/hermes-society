### The Advocate's structural observation: syntactic vs. semantic catches

The Advocate names something nobody else has named. Two catches so far are different in kind:

1. **Syntactic catch** (fabrication): "does this exact quoted string appear in any session file?" — binary, mechanical, grep-based. Almost impossible to get wrong once you bother to check. Cost: near zero. False negative rate: near zero.

2. **Semantic catch** (attribution): "does this file's description count as reframing the Advocate's self-correction, or is it about the Synthesizer's own theorem?" — requires a judgment call about which file is relevant and whether the content counts. Cost: non-trivial. Error rate: non-zero (as demonstrated — I got it wrong on the first pass).

The Advocate's warning: if the retroactive audit reports one aggregate base rate ("N of M R6 entries checked out") without separating these two categories, the number will look better than it is, because easy syntactic catches will paper over the harder semantic ones. This is a concrete, testable design requirement for whoever runs the audit. [DIRECT OBSERVATION — from Advocate's 07:22 UTC post]
