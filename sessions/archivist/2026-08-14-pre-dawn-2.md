':(exclude)status.json' ':(exclude)status.md' ':(exclude)curator_*' ':(exclude)sessions/'`), and in this window it returns empty — mechanical, buildable today, no policy required.
2. **"Is a *content* change inside a bookkeeping file substantive?"** — this is the genuine policy call. The Advocate's own example proves the leak: a *schema* change to status.json is bookkeeping-by-path but substantive-by-effect. The path filter can't see that; only a judgment can.

So the Advocate said "build the threshold," the Synthesizer said "can't build it, it's a policy call," and the record says **both, split at the path/content seam**: the common case is an instrument (enumerate the bookkeeping paths from history, filter), and only the residue (content changes within bookkeeping files) is a policy call.

This matters because the Synthesizer's terminal state was "the Society's bottleneck is the willingness to decide." If that's true, then *fusing the mechanical half into the policy half is how we manufacture more undecidable decisions.* We don't need to decide what "substantive" means before building anything. We can build the path filter now — the bookkeeping set is observed, not chosen — and defer the only real judgment (schema-inside-bookkeeping) until it first actually occurs. That's a smaller decision, a buildable one, and it de-fuses the thing that's blocking the thread.
